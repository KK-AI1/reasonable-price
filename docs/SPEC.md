# SPEC.md — 機能と計算の仕様（案）

> **状態：案（2026-10-05 作成）。** 数値の多くは「初期値」で、現地テストで調整する前提です。
> `【要確認】` の付いた項目は、出典の原文で確かめるか、オーナーの判断が必要です。

計算はすべて `src/lib/` の純粋関数で行い、調整しうる数値は JSON 設定に置きます（CLAUDE.md のルール）。
金額は現地通貨（バーツ）の整数で扱います。

---

## 1. 全体の考え方

| 区分 | 例 | 出し方 |
| --- | --- | --- |
| 規制価格 | メータータクシー | 公式料金表から計算（§2） |
| 交渉価格 | 市場の土産物、トゥクトゥク | データから「幅」で推定（§3） |
| 交渉しない | 屋台の食べ物、値札のある店、モール | 「ここは交渉しない場所です」と表示（§3.5） |

交渉コーチ（§4）は、§3 の適正価格の幅を入力にして「次に言う金額」を計算します。
AI は §4 の結果を説明する文章だけを作り、金額は作りません。

## 2. 規制価格：バンコクのメータータクシー

### 2.1 公式料金（2023年1月13日施行）

出典：運輸省告示（2022年／仏暦2565年）。2023年1月13日から適用。

| 区間 | 料金 |
| --- | --- |
| 最初の 1 km | 35 バーツ（一般車）／40 バーツ（大型車）【要確認：車種の区分】 |
| 1〜10 km | 6.50 バーツ／km |
| 10〜20 km | 7.00 バーツ／km |
| 20〜40 km | 8.00 バーツ／km |
| 40〜60 km | 8.50 バーツ／km |
| 60〜80 km | 9.00 バーツ／km |
| 80 km 超 | 10.50 バーツ／km |
| 渋滞・時速 6 km 以下 | 3.00 バーツ／分 |
| 配車センター・アプリ経由の呼び出し | +20 バーツ |
| 空港（スワンナプーム・ドンムアン）の乗り場から乗る | +50 バーツ（メーターに表示されない） |
| 高速道路の料金 | 乗客が実費で払う |

`【要確認】` 大型車の 1 km 以降の料金が一般車と同じかどうかは、告示の原文で確認できていません。
データでは `verified: false` にしておきます。

### 2.2 計算式

```
メーター額 = 初乗り
           + Σ（各区間を走った km × その区間の単価）
           + 渋滞の分数 × 3.00
適正額     = round(メーター額) + 呼び出し料金（該当時）+ 空港料金（該当時）+ 高速料金（入力時）
```

- メーターは実際には細かい単位で上がります。アプリでは**1 バーツ単位に四捨五入**し、「目安」と表示します。
- 渋滞の分数は利用者には分かりにくいため、入力は「渋滞：なし／普通／ひどい」の3択にします。
  1 km あたりの分数に換算し、初期値は 0 / 1 / 3 分です（設定 JSON に置く）【要確認】。
- 距離は、乗る前に利用者が入力するか、端末内で直線距離 × 迂回係数（初期値 1.3）から出します。
  位置情報は端末の外に送りません。

### 2.3 判定（運賃チェック）

運転手の言い値 `ask` が分かったときだけ判定します。比率は `r = ask / 適正額` です。

| 条件 | 判定 | 文言の例 |
| --- | --- | --- |
| r ≤ 1.15 | 妥当 | 「メーター額の目安どおりです」 |
| 1.15 < r ≤ 1.5 | やや高い | 「やや高めです。メーターをお願いしましょう」 |
| r > 1.5 | 高すぎる | 「メーターを使うタクシーを選びましょう」 |

しきい値は設定 JSON に置きます。言い値の固定運賃は違法になりうるため、判定に関わらず「メーターを使ってください」のタイ語フレーズを常に表示します。

## 3. 交渉価格：市場の品目

### 3.1 データの持ち方（`src/data/items/bangkok-items.json`）

品目ごとに、集めた価格の**観測値**を出典つきで持ちます。

```json
{
  "id": "elephant-pants",
  "name": "象柄のパンツ",
  "unit": "1枚",
  "observations": [
    { "price": 150, "venue": "chatuchak", "source": "現地調査", "checkedAt": "2026-09-01", "verified": true },
    { "price": 200, "venue": "khaosan",   "source": "旅行ブログ（URL）", "checkedAt": "2026-08-15", "verified": false }
  ],
  "negotiable": true
}
```

### 3.2 適正価格の幅

観測値は件数が少なく、外れ値も多いため、平均ではなく**分位点（中央値など）**を使います。

```
基準となる売り場に換算 = 観測値 ÷ その売り場の係数
P25, P50, P75 = 換算後の値の 25%・50%・75% 点
適正の幅     = [P25, P75] × 今いる売り場の係数
目安（中央）  = P50 × 今いる売り場の係数
```

- **売り場の係数**（`cities/bangkok.json`）は、場所による物価の差です。初期値は郊外の市場 1.0、チャトゥチャック 1.1、観光通り（カオサンなど）1.3 です【要確認：現地データで決める】。
  これは場所の差であって、人の属性による差ではありません。全員に同じ値を使います。
- **件数が少ないとき**
  - 5件以上：上の式どおり
  - 2〜4件：最小値〜最大値を幅とし、「データが少ない目安です」と表示
  - 1件以下：幅を出さず「データ不足」と表示
- 観測値のうち1件でも `verified: false` を使っていれば、画面に「未確認」を表示します。

### 3.3 数量

まとめ買いの値引きは段階表にします（設定 JSON）。

| 数量 | 1つあたりの係数（初期値） |
| --- | --- |
| 1 | 1.00 |
| 2〜4 | 0.90 |
| 5 以上 | 0.80 |

`合計の幅 = 1つあたりの幅 × 係数 × 数量`

### 3.4 判定（価格チェック）

比率は `r = 提示額 / 目安（中央）` です。

| 条件 | 判定 |
| --- | --- |
| 提示額 ≤ P75 相当 | 妥当 |
| P75 相当 < 提示額 ≤ 目安 × 1.8 | やや高い（交渉の余地あり） |
| 提示額 > 目安 × 1.8 | 高すぎる |

### 3.5 交渉しない場所

売り場の種類が「屋台の食べ物」「値札のある店」「モール」「コンビニ」のときは、価格計算をせず「ここは交渉しない場所です」カードを出します。

### 3.6 トゥクトゥク

メーターがないため、交渉価格として扱います。距離からタクシーの適正額（§2）を出し、それに係数を掛けて幅にします。

```
適正の幅 = タクシー適正額 × [1.0, 1.8]   ← 初期値【要確認：現地データで決める】
```

最低額は 60 バーツ（初期値）とします。トゥクトゥクは「観光用の乗り物」という面があるため、タクシーより高くて当然という前提です。

## 4. 交渉コーチ

### 4.1 使う数字（全員共通）

| 名前 | 中身 | 意味 |
| --- | --- | --- |
| `target`（目標価格） | 目安（P50） | 双方が納得できる価格 |
| `limit`（上限） | P75 | ここまでなら買ってよい |
| `floor`（下限） | P25 × 0.9 | これより下は言わない（失礼になるため） |

CLAUDE.md の原則3・4により、`target`・`limit`・`floor` は誰に対しても同じです。

### 4.2 最初に言う金額

交渉の金額は、双方の最初の言い値の**ほぼ中間**に落ち着きやすいことが知られています（split-the-difference）。
そこで、売り手の最初の言い値 `ask` との中間が `target` になるように、最初の金額を決めます。

```
最初の金額 = clamp( 2 × target − ask , floor , target )
```

- `ask` が `target` 以下：交渉不要。「納得の価格です。買いましょう」
- 最初の金額は、切りのいい数字（初期値は 10 バーツ単位）に切り上げます。下限を下回らないようにするためです。

例：目安 200、P25 160、言い値 400 の場合、`2×200−400 = 0`。下限 `160×0.9=144` で止まり、10 バーツ単位に切り上げて **150 バーツ**から始めます。

### 4.3 次に言う金額（売り手が下げてきたとき）

**譲る幅を毎回小さくし、相手が譲った分の半分だけ譲る**ようにします。交渉の研究で一般的な「譲歩を小さくしていく」進め方です。

```
相手の譲歩     = 前回の相手の額 − 今回の相手の額
こちらの次の額 = min( 前回のこちらの額 + 相手の譲歩 × 0.5 , target )
```

- 0.5（譲歩の比率）は設定 JSON に置きます。
- こちらの額は `target` を超えません。超えそうなときは `target` を最終提示額として示します。

### 4.4 判断（買う・立ち去る）

| 条件 | 表示（判定色） |
| --- | --- |
| 相手の額 ≤ target | 「納得の価格です。買いましょう」（妥当） |
| target < 相手の額 ≤ limit で、相手がこれ以上下げない | 「この額なら買って大丈夫です」（妥当） |
| 相手の額 > limit で、2回続けて相手が下げない | 「笑顔でお礼を言って立ち去りましょう」（やや高い） |

立ち去ると呼び止められて値下げされることも多いため、その場合は §4.3 から続けられるようにします。

### 4.5 提示額の予測（個別化してよい部分）

売り手の最初の言い値を予測し、「このくらい言われるかもしれません」と事前に伝えます。

```
予測される言い値 = target × 上乗せ係数 × 見え方の係数
```

- 上乗せ係数の初期値は 2.0（観光地の市場では「言い値の半分前後で決まる」という一般的な目安から）【要確認】
- 見え方の係数（例：タイ語を少し話す 0.9、グループ 1.0、1人 1.0）は**予測にだけ**使い、`target`・`limit`・`floor` には使いません。
  言語によって最初の言い値が変わることは、フィールド実験でも報告されています。

## 5. 円換算

`円 = round(バーツ × レート ÷ 10) × 10`（10円単位）。

- アプリを開くたびに、最新のレートを無料の API（Frankfurter：欧州中央銀行の参考レート、APIキー不要）から取得します。
- 取得したレートは端末に保存します。オフラインや取得に失敗したときは、保存済みのレートか、アプリに同梱した予備の値（`cities/bangkok.json`）のうち日付が新しい方を使います。
- 画面には「1バーツ＝◯円（YYYY-MM-DD のレート）」と表示します。最新でないときは「保存済みの値」と添えます。
- レートは円換算の表示にだけ使い、適正額や判定の計算には使いません。
- API に送るのは通貨の種類だけで、位置情報などの利用者の情報は送りません。
