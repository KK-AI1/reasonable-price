# VOICE.md — 「代わりに話す」交渉モード 仕様書

Claude Code はこのモードを作る・変えるときに、このファイルと `CLAUDE.md`・`SPEC.md`・`DESIGN.md` に従ってください。

---

## 1. 目的とイメージ

ユーザーがスマホのボタンを押すと、**スマホが現地語で代わりに話して**値引き交渉を進めるモード。
売り手の返事も聞き取って日本語に訳し、交渉コーチが「次に言う金額」を出す。

着想：ドラマ『VIVANT』の登場人物が、スマホの音声アプリを通して会話する姿。
**ただし、作品名・登場人物名・声優の声をアプリの中で使ったり、まねたりしない。** 機能名は「代わりに話すモード」とする。

### 1回のやり取りの流れ

```
[ユーザー] ボタンを押す「250バーツでどうですか？」
    ↓  金額は coach.ts が計算したもの
[スマホ] タイ語で読み上げ＋画面にタイ語を大きく表示
    ↓
[売り手] タイ語で返事「300なら売るよ」
    ↓  マイクボタンで聞き取る（または売り手が数字キーで入力）
[スマホ] 日本語訳を表示：「300バーツなら売る」
         金額を抜き出して確認：「相手の金額：300バーツ？」→ ユーザーが1タップで確定
    ↓
[交渉コーチ] 次の一手を計算 → 次のボタン「270バーツでどうですか？」を強調表示
```

## 2. 最重要ルール（CLAUDE.md の原則の続き）

1. **スマホが口にする金額は、必ず `coach.ts` の計算結果か、ユーザーが確定した数字だけ。** AIが金額を作ることは禁止。
2. **売り手の発言から抜き出した金額は、必ずユーザーが確認してから使う。** 自動で確定しない。
3. **話す文は「定型文＋金額の差し込み」が基本。** 定型文は事前に翻訳して JSON に持つ（オフラインで動く）。AIによる自由な翻訳は、売り手の発言を訳すときと、定型文にない言い回しが必要なときだけ。
4. **AIの出力に、渡していない金額が含まれていたら表示も読み上げもしない。**（検証関数を必ず通す）
5. **オフラインでも交渉が止まらないこと。** 音声認識や翻訳が使えないときは「数字キー」と「画面を見せる」で続けられる。
6. **特定の人物（声優・俳優）の声をまねたり、声を複製したりしない。** 端末の標準音声か、一般的な合成音声を使う。
7. **録音を保存しない。** マイクはボタンを押している間（または聞き取り中の表示が出ている間）だけ使う。

- ボタンはすべて日本語ラベル。押すと**タイ語で読み上げ**、画面上部にタイ語の文を大きく表示

- 「画面を見せる」：今の文と金額を全画面・特大文字で表示（DESIGN.md 6.4 と同じ）

## 4. 機能の詳細

### 4.1 定型文と読み上げ（オフライン対応）

`src/data/phrases/th.json` に定型文を持つ。金額は `{amount}` で差し込む。

```json
{
  "id": "offer",
  "ja": "{amount}バーツでどうですか？",
  "th": "{amount} บาทได้ไหมคะ/ครับ",
  "romaji": "{amount} バート ダイ マイ カ/クラップ",
  "polite_suffix": true
}
```

必要な定型文（最低限）：
- いくらですか？／高いです／{amount}バーツでどうですか？／まとめて買うと安くなりますか？
- {amount}バーツなら買います／考えます／ありがとう／メーターを使ってください
- 金額を入力してください（数字キーを渡すとき）

ルール：
- タイ語の丁寧語尾は、設定の「話し手」に合わせて `ครับ`（男性が使う）／`คะ`（女性が使う）を切り替える。**これは言語の文法上の選択で、価格には一切影響させない**
- 金額の読み上げ用に、数字をタイ語の数詞に変換する関数 `toThaiNumberWords(n)` を `src/lib/thai-number.ts` に作る（テスト必須）
  - 例：11 → สิบเอ็ด、20 → ยี่สิบ、21 → ยี่สิบเอ็ด、250 → สองร้อยห้าสิบ、1500 → หนึ่งพันห้าร้อย
- 画面表示はアラビア数字（250）＋タイ語の文。読み上げは数詞に変換した文
- 読み上げはまず端末の音声合成（Web Speech API の `speechSynthesis`、`lang: "th-TH"`）を使う
  - タイ語の音声が端末にない場合は、文字を大きく表示し「音声が使えないので画面を見せてください」と案内する
  - フェーズ後半で、クラウドの音声合成をサーバー関数経由で使う選択肢を追加してよい
- 読み上げ速度はやや遅め（rate 0.9）、音量は最大。市場は騒がしい前提
- 押してから読み上げ開始まで 1 秒以内

### 4.2 売り手の返事を聞き取る（オンライン時）

- 🎤 ボタンを押すと聞き取り開始。聞き取り中は画面全体で「聞いています」を表示し、もう一度押すと終了
- 音声認識はブラウザごとに対応状況が違う。次の順で使う：
  1. ブラウザの音声認識（`SpeechRecognition`、`lang: "th-TH"`）が使えれば使う
  2. 使えない・精度が悪い場合は、音声をサーバー関数へ送り、クラウドの音声認識で文字にする（音声は処理後すぐ破棄）
  3. どちらも使えなければ、🎤 ボタンを無効にして「数字キーを使ってください」と案内
- 文字になったタイ語は、サーバー関数経由で AI に日本語訳させ、画面に表示する

### 4.3 金額の抜き出し（ルールベースが先、AIは補助）

`src/lib/extract-amount.ts` に作る（テスト必須）。

1. アラビア数字（300）とタイ数字（๓๐๐）を探す
2. タイ語の数詞（สามร้อย = 300、ห้าสิบ = 50 など）を数字に変換して探す
3. 見つからない、または複数あって決められない場合だけ、AIに「この文に含まれる金額を、文中の表現そのままで返す」よう頼む。AIの答えは、元の文に該当する表現があるか検証してから使う
4. 抜き出した金額は「相手の金額：300バーツ？」と表示し、**ユーザーが「はい」を押すまで交渉コーチに渡さない**。「違う」を押したら数字キーで直せる

### 4.4 交渉コーチとの接続

- 確定した相手の金額を `coach.ts` に渡し、次の一手を計算
- 結果を「おすすめ」ボタンの文と金額に反映
- 「買いましょう」「立ち去りましょう」の判断が出たら、それぞれに合う定型文（「{amount}バーツなら買います」「ありがとう」）をおすすめボタンにする

### 4.5 AI に渡すプロンプトの原則（サーバー関数側）

- 役割：売り手の発言の翻訳、金額の表現の特定、丁寧な言い回しの提案だけ
- 「新しい金額を作らない」「入力にない数字を出力しない」と明記
- 応答は JSON で受け取り、`validateNoNewAmounts(output, allowedAmounts)` を必ず通す
- API キーはサーバー関数側だけに置く

---

## 5. プライバシーと配慮

- マイクの使用は、ボタンを押したときだけ。初回は「売り手の声を聞き取るためにマイクを使います。録音は保存しません」と説明して許可を取る
- 音声をクラウドに送る機能は、設定で ON/OFF できる（初期値：ON にする前にユーザーへ確認）
- 売り手を撮影・録音して保存する機能は作らない
- 定型文は丁寧語で。売り手を急かす・責める表現は入れない

---

## 6. 受け入れ条件

- [ ] 定型文ボタンを押すと、1秒以内にタイ語で読み上げが始まる（タイ語の音声がある端末で）
- [ ] 機内モードでも、定型文の読み上げ（端末の音声がある場合）、画面表示、数字キー、交渉コーチが動く
- [ ] スマホが読み上げる金額が、常に coach.ts の結果かユーザーが確定した数字と一致する（テストで確認）
- [ ] 売り手の発言から抜き出した金額は、ユーザーの確認なしに使われない
- [ ] `toThaiNumberWords` と `extract-amount` のテストが通る（1〜99,999 の範囲と境界値）
- [ ] AIの出力に新しい金額が含まれていたら、表示も読み上げもされない（テストで確認）
- [ ] 録音データが端末にもサーバーにも保存されない
- [ ] 作品名・登場人物名・特定の声の模倣がどこにもない
